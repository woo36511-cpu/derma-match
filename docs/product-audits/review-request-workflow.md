# 목록에 없는 제품 검수

홈과 첫 피부 설문에서 같은 제품 검색을 사용한다. 목록에 없는 제품은 로그인 없이 직접 담고 공식 자료를 찾아볼 수 있다. 검수 요청은 로그인한 계정만 보낼 수 있으며 제품명, 종류, 선택한 공식 링크만 받는다. 설문과 사용감은 이 요청에 포함하지 않는다. 입력된 링크는 팁이며, 서비스가 자동으로 접속하거나 공식 출처로 인정하지 않는다.

아누아와 마녀공장 제품을 담을 때는 로그인과 별개로 공식 사이트에서 확인을 시도한다. 카탈로그에 공식 주소가 없는 경우 브랜드 검색에서 제품명과 용량이 맞는 후보 하나를 찾는다. 단일 제품의 국내 고시에서 정확한 이름·용량과 완전한 전성분을 확인해야 성공한다. 세트, 여러 규격 후보, 보이지 않는 이미지 속 전성분, 읽을 수 없는 페이지는 기존 검수 요청으로 넘긴다. URL은 지정된 브랜드 호스트와 상품 상세 경로만 요청하며 다른 호스트로의 이동을 따르지 않는다. 공식 확인의 전성분과 출처는 이 기기에 최대 30일 저장한다. 자동 확인 제품은 사용 중인 제품으로만 해석하며 공식 성분 유무를 후속 질문과 성분 중복 확인에 쓴다. 새 추천 카탈로그에는 직접 올라가지 않는다. 보습 강도, 지속 시간, 공개되지 않은 함량은 이 방식으로 추정하지 않는다.

## 운영자 검수

1. Supabase SQL Editor에서 `status = 'pending'`인 요청 중 `id`, `product_name`, `category`, `source_url`만 읽는다. 요청자가 올린 링크는 곧바로 신뢰하지 않고 브랜드 사이트나 제조사의 국내 자료를 별도로 찾는다. 이미 요청된 제품의 이름과 종류가 같다면 한 번만 조사한다.
2. 브랜드·정확한 국내 판매명·용량·세대나 리뉴얼 여부와 완전한 국내 전성분을 대조한다. 같은 이름이라도 용량에 따라 처방이 다르거나 여러 버전 중 어느 쪽인지 확인할 수 없으면 임의로 매칭하지 않는다. 공개되지 않은 함량은 비워 두고, 판매자 문구만으로 수분감이나 보습 지속 시간을 만들지 않는다.
3. 확인된 경우 기존 카탈로그 규칙으로 `catalogExpansion.json` 또는 기존 제품의 전성분, 공식 자료와 검수 날짜, `careProfile` 근거를 등록한다. 제품의 사용감을 사용자 피부 수분 측정값으로 해석하지 않는다. 씻어내는 제품은 세안 후 사용감으로 따로 다룬다. 요청 이름이 정확히 같은 제품임을 확인한 경우에만 별칭을 추가한다. 검색 전용 항목을 승격한다면 `legacyLookupIds`를 써서 이전에 담은 항목과 사용감을 이어준다.
4. 카탈로그가 배포되고 검색과 첫 설문에서 제품 프로필이 연결된 것을 확인한 뒤에만 요청의 `status`를 `published`, `catalog_id`를 해당 카탈로그 ID로 변경한다. 자료가 부족하면 `status`를 `insufficient`, `catalog_id`를 `null`로 둔다. 검수되지 않은 제품은 표시되더라도 새 보습감 근거로 사용하지 않는다.

```sql
select id, product_name, category, source_url
from public.product_review_requests
where status = 'pending'
order by requested_at
limit 25;
```

같은 제품으로 확인된 기존 직접 입력은 다음 설문에서 검수된 프로필을 사용한다. 이미 저장된 설문은 당시 답을 그대로 유지한다. 공개 카탈로그에는 검수에 쓰는 공식 근거만 게시하고 요청자 정보와 요청 원문은 커밋하지 않는다.
