# 화장품 실사용 기록과 추천 검토

기본 제품을 추천한 뒤 사용자가 기존 제품 유지 또는 추천 제품 시작을 선택한다.
볼·얼굴 당김이 있으면 보습제와 수분 세럼, 세안 직후 당김을 답했다면 세안제를 기록할 수 있다.
세럼은 기본 루틴의 검수된 수분 세럼을 대상으로 시작한다. 특정 기능성 화장품·약이나
여드름 개선 데이터를 이 기록으로 대신하지 않는다.

| 범위 | 전후 기준 |
| --- | --- |
| 보습제 | 평소 관리 중 볼이 당긴 날 |
| 수분 세럼 | 세안 직후를 제외한 일상 중 볼이 당긴 날 |
| 세안제 | 세안 직후, 보습제를 바르기 전에 얼굴이 당긴 날 |

당김 일수와 별개로 최근 7일의 전반적인 피부 불편함을 같은 척도로 기록한다.
전후 비교에서 0일, 줄었지만 남음, 같음, 늘어남, 기억나지 않음을 구분한다.
14일 전 기록은 중간 확인이며, 자극이나 중단은 일찍 기록해도 이후 분석에서 지워지지 않는다.
이전 '오후 볼 당김' 기록은 같은 질문을 유지하며, 새 기록과 섞지 않는다.

개인 기록은 내부 분석 동의 없이도 남길 수 있다. 게스트는 이 기기에서만 사용하고,
로그인 사용자의 기록은 기존 계정별 저장소를 사용한다. 내부 집계는 기록 단위로 동의를
받고, 동의일부터 1년이 지나거나 철회하면 이후 집계에서 제외한다.

운영자는 `scripts/moisturizer-observation-report.sql`을 읽기 전용으로 실행한다.
같은 제품·확인 날짜·측정 기준에서 사람당 첫 기록을 쓰고, 수분 단계·민감 여부·시작 시
당김 일수·선택(시작/유지)별로 나눈다. 14~21일 응답과 미응답을 따로 세고, 거의 매일
답한 제품을 사용했고 다른 변화가 없던 응답을 별도로 비교한다. 중간과 이후의 자극 및
중단도 확인한다. `keep` 그룹의 제품 ID는 당시 추천 후보이며 실제로 쓴 제품은 식별하지
않는다. 그 그룹을 해당 제품의 사용 사례로 세면 안 된다.

추천 반영 절차:

1. 같은 측정 기준·제품·확인 날짜·수분 단계·민감 여부에 대해 시작과 유지, 두 당김 일수
   구간 모두 `enough_to_review`를 만족하는지 확인한다. 최소 50명, 일수 응답률 80%,
   비교 가능한 사용 응답률 70%는 운영상 검토 기준이다.
2. 자극·중단, 비교에서 빠진 기록, 함께 바꾼 제품이나 생활 조건을 함께 검토한다.
   응답이 확인되지 않은 경우를 개선 성공으로 세지 않는다. 피부 불편함도 악화하는지 살핀다.
   다음 기간에도 방향이 비슷하고 자극·중단이 늘었다는 신호가 없을 때만 적용을 검토한다.
   기존 제품 유지 여부는 사용자가 선택하므로 두 집단의 차이는 인과적 효능 추정치가 아니다.
3. 승인한 경우에만 `src/data/reviewedProductObservations.json`에 `protocol`, `productId`,
   `formulaVerifiedAt`, `hydrationLevel`, `sensitive`, `reviewedOn` (UTC 날짜)를 추가한다.
   개인 기록이나 소규모 집계값을 이 파일에 넣지 않는다. 같은 피부 조건과 제품 확인 날짜에
   한해 수분 단계가 정확히 맞고 기존 안전·성분 기준을 통과한 제품에 0.5점만 더한다.
   제품 확인 날짜가 달라지거나 검토 후 90일이 지나면 적용이 멈춘다.
   동의 철회는 이미 공개한 검토 결과를 실시간으로 다시 계산하지 않으므로 재검토 때 반영한다.

데이터가 충분하지 않으면 승인 목록을 빈 상태로 둔다. 판매 링크와 구매 여부는 이 판단에
사용하지 않는다.
