# 화장품 실사용 기록과 추천 검토

홈의 **다음 화장품 고르기**에서 사용자가 선택해서 남긴다. 추천 결과에는 기록
유도 카드나 비교표를 띄우지 않는다. 추천은 기록 없이 바로 받을 수 있고, 개인
전후 변화는 제품 기록이나 기존의 **내 피부 변화 보기**에서 열어볼 수 있다.

| 경로 | 시작 때와 다음에 같은 기준으로 비교하는 것 |
| --- | --- |
| 기초 세안·보습 | 세안 직후 당김, 일상 중 당김, 건조한 각질·번들거림이 있었던 일수 |
| 보습 보완 | 같은 부위의 건조·당김 또는 하얀 각질이 있던 일수 |
| 유분·모공 외관 | 번들거림이 신경 쓰인 일수 또는 모공이 눈에 띄는 정도 |
| 막힌 피지·결 | 붉지 않은 좁쌀·블랙헤드 개수 구간 또는 거친 느낌의 정도 |
| 톤·평평한 갈색 자국 | 같은 조명과 부위에서 보이는 정도 |
| 잔주름 | 같은 조명과 표정에서 보이는 정도 |

기초 제품은 설문에서 확인된 고민, 추가 제품은 저장된 추천 후보의 관리 목적에 한해
표시한다. 이미 잘 쓰던 제품을 그대로 유지하는 기록도 가능하다. 시작할 때 상태와 부위를
남기고, 다음에는 같은 질문과 함께 실제로 사용한 제품, 사용 기간과 빈도, 자극·중단,
동시 변화 여부를 받는다. 기간은 기록을 비교하기 위한 기준이다. 염증성 여드름,
모낭염처럼 보이는 돌기, 붉은 자국 및 솟거나 패인 흉터는 기존 개인 고민 기록에만
남긴다. 화장품의 해당 증상 치료 데이터나 의약품 전환 기준으로 사용하지 않는다.

비교에서 증상이 없었다는 응답, 줄었지만 남음, 변화 없음, 악화, 기억나지 않음을 구분한다.
당김·각질·유분은 14일, 외관·개수·결은 28일을 첫 비교 시점으로 사용한다. 중간 기록에서
자극·중단이 확인된 경우 이후 수치가 좋아져도 자극·중단 없는 사례에는 들어가지 않는다.
이전 ‘오후 볼 당김’ 기록은 같은 질문을 유지하며 다른 측정과 섞지 않는다.

개인 기록은 내부 분석 동의 없이도 남길 수 있다. 게스트는 이 기기에서만 사용하고,
로그인 사용자의 기록은 기존 계정별 저장소를 사용한다. 내부 집계는 기록 단위로 동의를
받고, 동의일부터 1년이 지나거나 철회하면 이후 집계에서 제외한다.

개인 추천은 다른 사람의 기록을 기다리지 않고 바로 조정한다. 새 추천에서 실제 쓴
제품의 자극 보고가 있으면 해당 제품을 제외한다. 전후 차이는 같은 제품 확인 날짜와
피부 조건·고민을 비교할 수 있고, 거의 매일 사용했으며 다른 변경이 없던 경우만
비슷한 후보의 순서를 조정하는 데 쓴다. 사용을 확인할 수 없는 기존 제품과 미응답은
특정 제품에 연결하지 않는다. 기록을 보유한 기기 또는 계정의 추천에만 반영하며,
내부 집계 동의와는 별개다. 결과에는 집계나 추천 점수의 계산 과정을 표시하지 않는다.

운영자는 `scripts/moisturizer-observation-report.sql`을 읽기 전용으로 실행한다. 사람당
제품·확인 날짜·측정 기준별 첫 동의 기록을 쓰고 수분 단계·민감 여부·관리 경로·부위·
시작 상태·선택(시작/유지)을 나눈다. 14~21일 또는 28~35일 응답, 미응답·미확인,
여러 변화가 있던 경우를 따로 센다. 거의 매일 실제로 답한 제품을 사용했고, 다른 변화가
없었던 응답만 제품별 비교 분모에 넣는다. 새 질문은 14일형에서 적어도 7일,
28일형에서 적어도 14일 사용했다고 답한 경우만 포함한다. `keep` 그룹의 제품 ID는 당시
추천 후보다. 실제로 쓴 기존 제품은 식별하지 않으므로 해당 제품의 사용 사례로 세면 안 된다.

추천에 반영할 때는 다음 순서를 따른다.

1. 같은 제품·확인 날짜·측정 기준·피부 조건·관리 경로와 부위에서 시작과 유지, 두
   시작 상태 구간이 모두 `enough_to_review`를 만족해야 한다. 각 그룹에서 최소 50명,
   결과 응답률 80%, 비교 가능한 사용 응답률과 전후 불편함 응답률 각각 70%를 요구한다.
2. 서로 겹치지 않는 두 모집 기간을 따로 내보낸다. 시작 그룹에서 자극·중단 없이
   증상이 없어진 비율이 유지 그룹보다 8%p 이상 높고, 자극·중단·불편함 증가 비율의
   차이가 각각 3%p 이하여야 한다. 두 기간에서 이 기준을 모두 통과한 조합만 검토한다.
   기존 제품 유지 여부는 사용자가 고르므로 두 집단의 차이를 인과적 효능으로 해석하지 않는다.
3. 운영자가 `node scripts/review-cosmetic-fit.cjs older.json newer.json`의 결과를 검토한다.
   이 명령은 검토 후보만 출력한다. 동의 철회, 표본 구성, 다른 변화, 빠진 응답을 확인한 뒤
   승인한 후보에 UTC 날짜 `reviewedOn`을 붙여 `src/data/reviewedProductObservations.json`에
   추가한다. 확인한 제품·성분 기준 날짜와 설문 조건이 현재와 일치해야 한다. 좁쌀·블랙헤드·
   갈색 자국은 해당 고민과 부위가 확인된 경우에만 반영한다. 개인 기록이나 집계값은 커밋하지 않는다.
4. 제품 확인 날짜, 추천 보습 단계, 민감 여부가 일치하고 기존 안전·성분 기준을 통과한
   제품에만 기초 0.5점, 추가 화장품 0.25점을 더한다. 검토 후 90일이 지나거나 제품
   확인 날짜가 달라지면 적용이 멈춘다. 동의 철회는 재검토에 반영한다.

검토할 데이터가 없으면 승인 목록은 빈 상태로 둔다. 판매 링크와 구매 여부는 사용하지 않는다.

기간은 UTC 시작일 포함·종료일 제외다. 한 트랜잭션에서 `BEGIN READ ONLY` 후
`SET LOCAL dearsince.report_start = 'YYYY-MM-DD'`, `SET LOCAL dearsince.report_end = 'YYYY-MM-DD'`로
실제 날짜를 지정하고 SQL 본문을 실행한 뒤 `ROLLBACK`한다. 첫 기록을 고른 뒤 기간을
적용하므로 한 사람이 같은 제품과 확인 날짜·측정 기준으로 두 기간에 동시에 잡히지 않는다.
각 집계 파일은 `{"periodStart":"YYYY-MM-DD","periodEnd":"YYYY-MM-DD","rows":[...]}` 형식으로
저장한다. `rows`는 SQL의 집계 행이며 날짜는 문자열, 집계값은 숫자로 내보낸다. 두 기간의
집계에 행이 없는 경우 빈 배열을 사용한다. 날짜가 행의 `period_start`·`period_end`와 다르면 검토 명령은 중단한다.

## 시술 정보와 화장품 기록

기본 루틴과 추가 고민 결과에서 사용자가 **피부과 시술 선택지 보기**를 눌렀을 때만
해당 고민의 정보를 표시한다. 흉터 모양을 구분하기 어려우면 특정 시술을 고르지 않는다.
염증이 진행 중이거나 급성 자극·악화가 확인되면 미용 시술을 붙이지 않는다. 큰 여드름
병변의 주사는 국소적이고 해당 고민을 고른 경우의 의료 정보로만 표시한다. 선택을
저장하거나 화장품 추천 점수에 사용하지 않는다. 같은 부위에 새로 받은 시술은
화장품 후속 기록에서 다른 변화에 포함하도록 안내한다.
