# Journey 8축 변화와 실사용 기록 신뢰도

2026-10-11 반영. Journey 저장 스키마는 3, 측정 버전은 `survey-8-axis-v1`,
신뢰도 규칙 버전은 `usage-record-v1`이다. 저장 위치는 기존 브라우저 localStorage이며
로그인·서버 저장과 추천 점수 자동보정은 다음 단계다.

## 같은 기준의 Before/After

건조함, 번들거림, 속당김, 민감 반응, 장벽 부담, 모공 막힘, 트러블 활동,
붉은 트러블의 8개 축을 0~10 설문 신호로 저장한다. 높은 값은 해당 신호가
많다는 뜻이며 수분감 루틴 단계나 임상 측정값과 다르다.

첫 진단은 `skinMeasurement`, 피드백은 `outcome.skinComparison`에 이전·현재
측정과 측정 시각, 기준 버전, 기준 기록 ID, `현재 - 이전` 변화량을 저장한다.
재평가 원문 응답도 `followUpSurveyAnswers`에 보관한다.

누락, 비수치, 범위 밖 값은 `null`이다. 측정한 0과 누락을 구분하며 기준 버전이
다르면 변화량을 계산하지 않는다. 설문 점수나 정규화 방식을 바꿀 때는 측정
버전도 반드시 변경한다. 기존 v2 기록은 같은 설문을 썼으므로 기존 값이 있을
때만 호환 표시한다. 빠른 추천 첫 체크는 이전 측정이 없어 비교 불가로 저장하고,
다음 체크부터 바로 앞 체크와 비교한다. 누락된 직전 측정을 건너뛰고 최초 진단을
사용하지 않는다.

## 제품별 실제 사용

꾸준히 사용, 가끔 사용, 사용 후 중단, 전혀 사용하지 않음을 구분한다.
추가 입력은 사용한 날 수·빈도·권장량 대비 사용량·중단 여부/이유·자극 여부·
안내 사용법 준수 여부다. 입력하지 않은 정보는 추정하지 않는다.
세부 입력은 선택 사항으로 기존 피드백 진행을 막지 않는다.

## 신뢰도 규칙

`dataReliability.score`는 자체 규칙에 따른 기록 충분함 점수(0~1)다.
제품 효능 확률이나 검증된 통계 신뢰도는 아니다. 0.8 이상 high(기록 충분),
0.55 이상 medium(일부 정보 부족), 나머지 low(판단 근거 부족)로 표시한다.

- 루틴 사용·기간 및 5가지 생활/환경 변화 질문 중 미응답 또는 미지원 답변이
  있으면 최대 0.5. 기존 기간·루틴 준수·생활 변화 감점도 반영한다.
- 제품별 필수 사용 세부정보가 빠지면 해당 제품은 최대 0.5.
- 8축 비교가 완전하지 않으면 최대 0.4.
- 7일 미만은 최대 0.35, 7~13일은 최대 0.65. 14일은 데이터 수집 기준이며
  제품의 효과가 나타나는 보장 기간이 아니다.
- 드문 사용은 최대 0.35, 가끔/주 몇 회 사용·사용법 미준수는 최대 0.65,
  사용 중단은 최대 0.5. 사용하지 않음·미확인·모순된 중단 응답은 0.
- 루틴 기록 점수는 사용한 제품 점수 중 가장 낮은 값으로 제한한다.
- 중단한 제품도 해당 기간에 영향을 줬을 수 있으므로 노출 제품에 포함한다.
  명시적으로 전혀 사용하지 않았다고 답한 제품만 제외한다.

완전한 8축 비교, 생활 변화 없음, 모든 제품의 사용 여부 확인, 단일 제품의
충분한 사용 기록이 함께 있을 때만 `productAttributionReady`를 true로 저장한다.
그 뜻은 `single_product_association`(연관성 검토 가능)이며 인과 효과 확정이
아니다. 여러 제품 사용은 `routine_observation`으로 남는다.
`automaticScoreAdjustmentReady`는 항상 false다.

결과 화면과 Journey 기록에 8축 표·신뢰도 사유·제품 사용 요약·생활 변화 응답을
표시한다. 같은 세션에서 피드백을 다시 선택하면 동일 기록을 수정하고, 평가한
이전 루틴과 기준 측정을 유지한다. 다음 체크를 시작할 때는 입력을 초기화한다.

## 검증

Jest는 누락값/실측 0, 기준 버전 불일치, 기존 기록 호환, 빠른 추천의 첫/다음
체크, 사용 정보 부족·중단·복수 제품·단일 제품 조건을 검사한다. 앱 회귀 테스트는
실제 입력→저장→결과 표시→수정→다음 체크→재열람 흐름을 검사한다.
